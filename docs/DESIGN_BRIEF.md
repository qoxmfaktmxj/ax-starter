## 2. 사용 장면과 화면 구조

모드는 Operate다. 사원관리 담당자가 검색 결과를 비교하고 여러 행을 고친 뒤 한 번에 저장한다. 최초 화면에서 '현재 조회 조건', '전체/현재 건수', '변경 건수', '저장할 수 있는지'를 바로 구분해야 한다.

```text
상단: AX Starter / 사원관리                     사용자 / 로그아웃
왼쪽 메뉴       사원관리              조회 조건과 결과 건수
사원관리        사번 [      ] 이름 [      ] 조직 [   ] 상태 [   ] 조회
감사 기록       조회형 / 일괄편집        변경 3건  추가  삭제  저장  Excel  PDF
                -------------------------------------------------------
                선택 상태 사번  이름       조직       입사일     월급
                [ ] 수정 E001 가상사원01   가상조직A   2024-01-31 ...
                ... 넓은 작업 Grid ...
                -------------------------------------------------------
                저장/검증 결과, 조회 한도 안내
                                          오른쪽: 상세 / 첨부 / 출력 작업
```

로그인, 사원관리, 관리자 감사 조회가 전체 화면 범위다. 별도 대시보드/KPI 카드/소개 hero를 만들지 않는다. 상세 패널은 조회한 사원의 기본 정보와 첨부만 갖고 비밀번호/민감 identity를 표시하지 않는다.

로그인은 [ISU 로그인 설계](superpowers/specs/2026-09-24-isu-login-design.md)를 따른다. 얼음 블록 ISU 3D 장면, 서리 유리 패널의 아이디/비밀번호 로그인, 작은 SSO 로그인으로 구성한다. OIDC fixture 로그인 화면을 실제 회사 인증으로 오해하지 않도록 local 안내를 둔다.

Brand base -> semantic -> component의 3단계로 연결한다. `packages/grid/theme.ts`는 semantic/density 토큰을 AG Grid로 변환한다. 각 화면에서 색/높이를 제각각 하드코딩하지 않는다. 브랜딩 설정 UI와 여러 팔레트(테마) 기능은 ISU 로그인 교체 다음 최우선 과제로 별도 설계한다.

입력과 버튼의 경계는 흰 작업면에서 3:1을 확보하는 별도 control border 토큰을 사용한다. 표 구분선과 패널 테두리의 낮은 대비 토큰과 구분한다.

v4 Blue/Lime은 kickoff에서 가설로 내려갔다. 오늘 실제 AI 기능이 없으므로 Lime 배지나 AI 반짝이 아이콘을 억지로 넣지 않는다. 전체 Dark Mode는 테마 시스템 과제에서 함께 다룬다.

## 4. 조작 계약

- 단일 클릭은 셀 선택, 더블 클릭/키보드로 편집한다. 체크박스는 행 선택이다.
- 추가는 편집 집합에 신규 행을 넣는다. 삭제는 대상 이름을 확인하고 기존 행을 삭제 예정으로 표시한다. 실제 DB 삭제는 저장 시 적용한다.
- toolbar는 조회, 추가, 삭제, 저장, Excel, PDF 순서로 실제 지원 기능만 보여준다. 원본의 복사/템플릿/업로드 버튼을 빈 동작으로 재현하지 않는다.
- 검색 draft와 적용된 조건을 구분한다. 조회형/일괄편집형 의미를 레이블로 표시한다. 전체 선택처럼 범위가 불분명한 버튼을 쓰지 않는다.
- '저장 3건'으로 변경량을 보인다. 저장 실패는 입력을 남기고 첫 오류 행/필드로 이동한다. 충돌은 자동 덮어쓰기 대신 현재 데이터 다시 읽기와 입력 보존을 안내한다.
- 파일은 검사 대기/면제/다운로드 가능/삭제 중을 문자로 표시한다. 격리 파일에 활성 다운로드 버튼을 보여주지 않는다.
- Excel/PDF 작업은 대기/생성 중/완료/권한 회수/실패를 보여준다. 누르면 즉시 파일이 있는 것처럼 가짜 완료를 표시하지 않는다.
- 닫히는 Dialog/Panel은 실제 진입 버튼으로 포커스를 돌린다. 로딩/오류/완료 문구는 상태 영역으로 읽힌다.

## 5. 화면 상태와 검증 데이터

가상 데이터 24명, 긴 조직명, 큰 금액, 동명이인, 빈 값, 3개 이상 validation 오류를 기준으로 삼는다. 새 UI의 e2e fixture와 screenshot fixture를 공유한다.

| 상태 | 보여줄 내용 |
| --- | --- |
| 로딩 | 표 구조 유지, 중복 작업 비활성화 |
| 결과 없음 | '조회 조건에 맞는 사원이 없습니다'와 조건 초기화 |
| 조회 실패 | 원인 범주와 다시 조회, 내부 오류/SQL 제외 |
| 권한 없음 | 허용되지 않는 작업 안내, 보호 데이터는 렌더링하지 않음 |
| 입력 오류 | 행/필드 단위 메시지와 수정 위치 |
| 충돌 | 다른 저장으로 변경됐다는 안내, 자동 재시도/덮어쓰기 없음 |
| 미저장 | 변경 건수, 이동 전 저장/계속 편집/버리기 선택 |
| 성공 | 저장 건수와 결과, dirty 초기화 |

데스크톱 1366x768와 1440x900에서 검색/toolbar와 첫 여러 행이 바로 보여야 한다. 구현은 390x844에서도 메뉴/검색을 접고 Grid만 지역 가로 스크롤을 허용하는 구조로 만든다. 모바일에서 복잡한 일괄 편집 최적화는 오늘 범위 밖이다. 모바일 로그인/조회/상세/오류 안내의 전수 확인과 완성 판정은 P1이며 오늘 검증 완료로 주장하지 않는다.

P0 검증: 데스크톱 정상/오류/충돌 상태, 키보드 Tab/Enter/Escape, 레이블/포커스, 일반 텍스트 대비 4.5:1, 큰 텍스트/컨트롤 대비 3:1, body 가로 overflow와 reduced motion을 확인한다. desktop 캡처에서 큰 결함을 한 번에 고친 뒤 재확인한다. P1 검증: 자동 axe serious/critical 0, 390 모바일 전수 흐름/캡처/회귀. P1 미실행을 통과로 표시하지 않으며 픽셀 일치/90점 달성을 근거 없이 선언하지 않는다.

## 6. 제외와 후속

사용자는 위 결합 방향을 선택했다. 기존 kickoff의 A/B 두 시안 선택 요구는 이번 선택으로 방향이 결정된 상태다. 구현 후 화면 확인은 필요하지만 오늘 다시 두 개의 완성 UI를 만들 필요는 없다.

금지: 카드 반복, 그라데이션 글자/보라 그라데이션, 의미 없는 아이콘/배지, 영문 fallback에 맡긴 한글, Grid 행 애니메이션, 외부 CDN 폰트.

Vibe HR의 range paste, fill handle, undo/redo, 현재 페이지 pivot/통계 기능은 그 제품의 독립 기능이다. Starter에 범위가 확장된 것으로 해석하지 않는다. 자체 Grid 두 모드와 원자적 저장부터 완성한다.
