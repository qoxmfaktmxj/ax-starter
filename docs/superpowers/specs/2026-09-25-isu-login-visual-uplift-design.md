# ISU 로그인 그래픽 고도화 설계

기준일: 2026-09-25. 상태: 사용자 승인. 선행 설계: [ISU 로그인 설계](2026-09-24-isu-login-design.md). 브랜치: `feat/isu-login-visual`.

## 1. 목표

로그인 3D 장면을 igloo.inc 수준의 분위기로 끌어올린다. **목표 점수는 igloo.inc 대비 80점 이상**(7절)이다. 코드만으로 먼저 끝까지 다듬고, 80점에 못 미치면 부족한 항목만 블렌더 에셋으로 바꾼다(8절). 블렌더 5.2.1 LTS는 `C:\Program Files\Blender Foundation\Blender 5.2\blender.exe`에 설치되어 있다.

igloo.inc의 모델, 텍스처, 코드 파일은 가져오지 않는다. 기법과 분위기만 참고하고 에셋은 직접 만든다.

## 2. 사용자 피드백과 결정

| 피드백 | 결정 |
| --- | --- |
| 맨 아래 블록이 들리지 않는다 | 모든 블록이 반응한다. 맨 아래 단은 움직임 폭 50% |
| Share the Future가 없다 | 평소 불투명도 0.35로 옅게, 로그인 성공 시 1로 진하게. 정지 화면에서도 옅게 |
| 초록 점 위치가 로고와 다르다 | 로고 실측대로 I 기둥의 왼쪽 위 대각선, 모서리가 맞닿게 |
| ISU 글자가 파랑이 아니다 | 블록 기본색을 ISU 파랑 #0090D0으로 |
| 초록과 돌을 그래픽적으로 다듬는다 | 3절, 4절 |
| igloo.inc처럼 이쁘게 | 3~6절, 80점 목표 |

선행 설계에서 바뀌는 점: 글자는 소문자 원호형에서 **로고 실측 대문자 ISU**로, 슬로건 Share는 숨김에서 옅게 표시로 바뀐다. 블루아워 배경, 서리 유리 패널, 인증, 폼 동작은 그대로다.

## 3. 로고 실측과 블록 배치

`Downloads/introduction_logo.jpg`(306x67)를 픽셀 단위로 실측한 값(단위: 로고 픽셀, y는 아래로 증가)이다.

| 요소 | 범위 |
| --- | --- |
| 초록 사각형 | x 1~15, y 0~14 (15x15) |
| I | x 15~29, y 14~66 (15x53) |
| S | x 42~76, y 14~66. 윗막대 y 14~27(왼쪽 위 모서리 둥금), 대각선 획 중심 (51,30)에서 (67,51)로, 아랫막대 y 53~66(오른쪽 아래 모서리 둥금) |
| U | 왼쪽 기둥 x 88~102, 오른쪽 기둥 x 112~126, y 14~50. 바닥 y 50~66, 양쪽 아래 모서리 둥금 |
| 글자 사이 | I와 S 12, S와 U 11 |

월드 변환: 글자 높이 53 로고 픽셀 = 3.1 월드 단위(1 로고 픽셀 = 3.1/53). 블록 두께 0.7, 블록 사이 틈 0.06(틈새 빛이 보이도록 선행 설계의 0.03에서 넓힌다). 글자 바닥 y=0, 전체 가운데 x=0.

| 글자 | 블록 |
| --- | --- |
| I | 기둥 5단, 초록 큐브 1개(기둥과 같은 폭, 기둥 윗부분 왼쪽 위에 대각선으로 맞닿음) |
| S | 윗막대 3개(왼쪽 끝 블록의 바깥 모서리 둥금), 대각선 3개(획 방향으로 기울임), 아랫막대 3개(오른쪽 끝 블록의 바깥 모서리 둥금) |
| U | 왼쪽 기둥 4단, 오른쪽 기둥 4단, 바닥 3개(양 끝 블록의 바깥 아래 모서리 둥금) |

합계 26개. 배치는 WebGL과 분리된 순수 모듈(`isu-layout.ts`)로 유지하고 단위 테스트한다. 블록 명세는 중심, 크기, z축 회전, 둥근 모서리(없음, 왼쪽 위, 오른쪽 위, 왼쪽 아래, 오른쪽 아래 중 하나), 글자, 초록 여부, 단 번호를 가진다.

## 4. 블록 형태와 재질

- 형태: 모서리를 둥글린 상자를 촘촘히 나눈 뒤 저주파 잡음으로 면을 울퉁불퉁하게, 고주파 잡음으로 모서리를 깨진 듯 깎는다. 블록마다 크기 +-6%, 회전 +-3도 편차를 주되 배치 테스트의 범위 안에 둔다. 둥근 모서리 블록은 해당 모서리를 블록 높이만큼의 반지름으로 깎는다.
- 파랑 얼음돌 재질: 기본색 #0090D0. 위를 향한 면에는 눈이 얹힌 흰색을 섞는다. 월드 좌표 기준 여러 크기의 결(기존 CC0 텍스처와 잡음)을 겹친다. 모서리와 이음새는 밝은 서리 빛, 가장자리는 옅은 림 라이트.
- 초록 큐브: #A0C840 반투명 코어가 안에서 빛난다. 테두리는 밝고 면은 서리 결. 약 3초 주기로 밝기가 숨 쉬듯 바뀌고 주변 블록과 바닥에 연두 빛이 번진다.

## 5. 빛, 분위기, 후처리

- 틈새 빛: 글자마다 블록 뒤에 빛나는 심을 둔다. 블록 틈으로 푸른 흰빛이 새어 나오고, 블록이 벌어질수록 심과 틈새 빛이 강해진다.
- 바닥 빛: 글자 아래에 방사형으로 번지는 빛 면을 둔다.
- 그림자: 실시간 그림자에 GTAO(접촉과 틈새 그림자)를 더한다. 터치 기기에서는 GTAO를 끈다.
- 분위기: 블루아워를 유지하고 땅 근처가 짙은 높이 안개를 더한다.
- 후처리 순서: 장면, GTAO, 빛 번짐, 색 보정(대비, 톤), 필름 그레인, 비네트, 약한 색수차, 출력.

## 6. 움직임, HUD, 슬로건

- 포인터 반응과 자동 움직임은 모든 블록에 적용한다. 맨 아래 단은 폭 50%.
- 등장: 블록이 흩어진 위치에서 날아와 순서대로 쌓이며 살짝 튀고 멈춘다(PC 2.6초, 터치 1.8초). 텍스처 로딩 중 윤곽선 미리보기는 유지한다.
- HUD는 사용자 결정으로 제외(2026-09-26). 포인터 근처 블록에 흰 선과 번호 라벨을 그리는 HUD는 구현하지 않는다. 포인터를 올리면 블록이 벌어지고 틈이 밝아지는 반응은 그대로 둔다.
- 슬로건: Challenge는 등장이 끝나면 선명하게, Share는 평소 불투명도 0.35, 로그인 성공 시 1. 옅은 Share는 장식이므로 대비 검사는 Challenge(항상)와 Share(성공 상태)에만 3:1을 요구한다.
- 성공 연출(연두 빛이 이음새를 따라 퍼짐), 입력 중 잠잠해짐, 실패 떨림은 유지한다.

## 7. 점수 측정

- 캡처: 같은 1440x900 화면에서 우리 로그인(등장 완료, 포인터를 블록 위에 둔 상태와 둔 전 상태)과 igloo.inc 첫 화면을 캡처한다.
- 항목(각 100점, 6개): 블록 형태, 재질 디테일, 빛과 틈새 발광, 분위기(안개와 깊이), 후처리와 색감, 움직임과 반응. HUD와 타이포 항목은 HUD는 사용자 결정으로 제외(2026-09-26)로 없앤다.
- 채점자: 메인 세션과 독립 리뷰 에이전트(opus)가 따로 채점하고 평균을 낸다. **6항목 평균 80점 이상**이 통과다.
- 성능 조건: 실제 GPU 브라우저에서 1440x900 기준 50fps 이상. 미달이면 품질 설정을 낮춰 맞춘 뒤 다시 채점한다.
- 채점 결과와 캡처 경로는 PROGRESS에 기록한다.

## 8. 블렌더 전환 (2026-09-25 결정)

Task 1 중간 캡처를 본 사용자가 블록 형태가 어색하다고 판단해, 코드 방식 채점을 기다리지 않고 **블록 형태와 굽기를 지금 블렌더로 만든다.** 빛, 후처리, HUD, 채점은 코드로 계속한다.

- 입력: `isu-layout.ts`의 26개 블록을 `tools/blender/isu-layout.json`으로 내보낸다. 단위 테스트가 JSON과 `buildIsuLayout()` 결과가 같은지 확인한다.
- 스크립트: `tools/blender/build_isu_blocks.py`를 블렌더 5.2.1에서 화면 없이 실행한다. 블록마다 상자를 만들고 로고의 둥근 모서리를 크게 깎은 뒤, 작은 모서리 깎기, 촘촘한 리메시, 잡음으로 면의 울퉁불퉁함과 Voronoi 균열 형태의 깨진 모서리를 만든다. 스마트 UV를 펼친다.
- 굽기: 바닥면과 이웃 블록을 둔 채 Cycles로 AO를 정점 색에 굽는다. 정점 색 R=AO, G=모서리 마모(곡률 계산), B=블록별 색조 편차.
- 출력: `apps/web/public/models/isu-blocks.glb`(Draco 압축, 재질 없음, 노멀, UV, 정점 색). 블록 이름은 `block-00`~`block-25`로 배치 순서와 같다. 확인용 렌더 `output/blender/isu-blocks-preview.png`.
- 좌표: three (x, y, z)를 블렌더 (x, -z, y)로 두고 `export_yup`으로 되돌린다. 블록 회전은 블렌더 Y축 기준 `-rotation`이다.
- 웹: GLTFLoader와 DRACOLoader로 불러오고 해독기 파일은 `apps/web/public/draco/`에서 제공한다(외부 CDN 없음). 블록 위치와 회전은 배치 데이터와 편차로 다시 정하고, 모델에서는 형태만 쓴다. 재질은 기존 파랑 얼음돌 셰이더에 굽기 값(AO, 마모, 색조)을 더한다.
- 출처: 스크립트, 블렌더 버전, 입력 JSON을 `apps/web/public/models/provenance.json`에 기록한다. 외부 에셋은 쓰지 않는다.

## 9. 테스트와 검증

- 단위: 새 배치 모듈. 블록 수 26, 초록 큐브가 I 기둥 윗부분 왼쪽 위에 모서리가 맞닿음, 글자 순서와 간격, 전체 가운데 x=0, 바닥 y=0, 둥근 모서리 블록 위치, 단 번호. 움직임 모듈에서 맨 아래 단 계수 0.5.
- e2e: 기존 로그인, 장면, 대체 화면 검사를 유지한다. Share 기본 불투명도 0.35와 성공 시 1, Challenge 대비 3:1, 성공 상태 Share 대비 3:1을 추가한다. HUD 오버레이 검사는 HUD는 사용자 결정으로 제외(2026-09-26)로 없앤다.
- 정지 이미지 두 장을 새 장면으로 다시 캡처한다.
- 완료 조건: `pnpm check`, `pnpm test`, `pnpm test:integration`, `pnpm e2e`, `pnpm build` 통과, 7절 80점 이상, 50fps 이상.
