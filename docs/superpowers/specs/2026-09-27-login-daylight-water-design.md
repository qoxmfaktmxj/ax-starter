# ISU 로그인 연속 하루와 수면 질감 설계

기준일: 2026-09-27. 이 문서는 [ISU 수면 로그인 적용 기준](2026-09-26-isu-water-login.md)의 분위기 순환, 해 궤도, 수면과 포인터 물결 결정을 대체한다. 블록, 슬로건, 로그인 카드, CI 색, 입력 중 억제와 모션 감소 대체 결정은 그대로 유지한다.

## 배경과 목표

사용자는 현재 로그인 배경이 2010년대 3D 화면처럼 보인다고 판단했다. 목표는 전문가가 만든 로그인 배경 수준의 물, 해, 하늘이다. 사용자가 지목한 문제는 세 가지다.

1. 물 질감이 판처럼 보인다. 원인은 단색 판 위에서 반사 이미지를 sin 파형으로 흔들고, 각도별 반사율과 실제 잔물결 법선이 없는 셰이더다. 수평선의 회색 띠는 180 단위 수면 판의 끝이 실제 수평선보다 약 1.8도 아래에서 끝나 하늘 구의 아래쪽이 약 33px 보이기 때문이다.
2. 수면 호버 흔들림이 크고 부자연스럽다. 현재 포인터 자취는 반사 좌표를 최대 0.04까지 비틀고 길이가 2.3 단위 이상이다.
3. 해가 뒤에서 뜨고 뒤에서 지며, 크고 평평한 원판과 넓은 후광이 촌스럽다. 하늘은 고정 장면 6개의 2색 그라디언트를 섞는다.

## 사용자 결정

- 하루 한 바퀴는 2분이다. 해가 떠 있는 동안 일정한 속도로 움직이고 완전한 밤만 빠르게 지나간다.
- 비 오는 저녁 장면은 뺀다. 라벤더 잔광은 황혼에서 자연스럽게 나타나므로 따로 두지 않는다.
- 방식은 직접 구현이다. 대기 산란 하늘, Blender에서 구운 잔물결 법선, 빛 번짐 후처리, 작은 파동 계산을 사용한다. three.js 기본 Sky와 Water, 미리 렌더한 영상은 쓰지 않는다.
- 참고 사진은 `C:/Users/sp20171217yw/Downloads/참고이미지/`의 세 장이다. `물비치는질감.png`에서 잔물결에 끊긴 거울 반사와 수평선 안개, `물의질감및 해 표현.PNG`에서 촘촘한 잔물결, 깊은 청색과 반짝임으로 된 햇빛 길, `지평선끝표현.jpg`에서 선명한 수평선과 그 위로 밝게 빠지는 하늘만 참고한다. 사진 픽셀, 숲, 배, 워터마크는 제품 자산에 넣지 않는다.

## 1. 하루 시간과 해 궤적

`apps/web/app/login/isu-water-moods.ts`를 `isu-day-cycle.ts`로 교체한다. 고정 장면, 15초 유지와 5초 전환을 없앤다. 입력은 주기 안의 시각 `t`(0 이상 120 미만의 초)이고 출력은 해 방향(고도, 방위)이다. 이 모듈은 three, Next, DOM을 import하지 않는 순수 함수다.

- 좌표: 카메라는 서쪽(-z)을 본다. 동쪽은 +z(카메라 뒤), 남쪽은 -x(왼쪽), 북쪽은 +x(오른쪽), 위는 +y다.
- 궤적: 위도 45도, 적위 +15도에 해당하는 원 궤적이다. 일출은 카메라 오른쪽 뒤(북동), 정오는 왼쪽 위 남쪽 고도 60도, 일몰은 정면에서 북쪽으로 약 21.5도다. 데스크톱 1440x900에서 일몰 지점은 화면 x 약 62%로 U와 로그인 카드 사이다. 적위 상수 하나로 일몰 위치를 조절한다.
- 속도: 해 고도가 -6도 이상인 동안 시간각이 일정한 속도(약 2.4도/초)로 움직인다. -6도 아래에서는 속도가 부드럽게 빨라져 완전한 밤(고도 -12도 미만)은 약 15초다. 이 값으로 새벽과 노을 구간(고도 +10도에서 -8도)은 각각 약 11.5초, 오후에 해가 화면 위쪽에서 수평선까지 보이는 시간은 약 10초다.
- 첫 진입 시각만 `Math.random`으로 정한다. 이후 벽시계 경과 시간으로 진행한다.
- 입력 중 억제: 기존 `calm` 상태에서는 해의 진행을 부드럽게 멈춘다. 입력이 끝나면 다시 진행한다. 페이지가 보이지 않을 때 시간이 건너뛰지 않는 기존 동작을 유지한다.
- 시간대 이름: 해 고도와 오전/오후로 새벽, 일출, 아침, 한낮, 오후, 노을, 황혼, 밤 중 하나를 정한다. 검사와 캡처 식별에만 쓰고 렌더링 분기에는 쓰지 않는다.

## 2. 하늘과 조명

- 하늘 구 셰이더를 단일 산란 대기 계산(레일리, 미, 오존 흡수, 행성 그림자)으로 바꾼다. 해 방향만 입력한다. 일출 때 정면 하늘의 분홍 띠와 푸른 지구 그림자, 한낮의 청색에서 수평선으로 밝게 빠지는 하늘, 노을의 주황, 해가 진 뒤의 라벤더와 푸른 시간이 같은 계산에서 나온다.
- 수평선 아래 방향의 하늘 구는 물 색과 안개로 채워 수면 판 끝과의 이음새가 보이지 않게 한다.
- 해는 작은 HDR 원판에 가장자리 어두움을 준다. 후광은 셰이더의 넓은 원으로 그리지 않고 빛 번짐 후처리(three의 `UnrealBloomPass`)로 만든다. 높은 임계값으로 해, 반짝임, 강한 반사광만 번지게 한다.
- 밤에는 셰이더 해시로 만든 별이 해 고도에 따라 서서히 나타난다. 달 원판은 넣지 않고 약한 푸른 방향광만 둔다.
- 하늘 그라디언트의 띠 무늬를 막기 위해 출력 전에 미세한 디더링을 넣는다.
- ISU 조명: 햇빛 색과 세기는 하늘 셰이더와 같은 대기 투과 식을 JS로 옮겨 계산한다. 주변광은 같은 계산의 천정과 수평선 색에서 가져온다. 해 고도에 따라 노출을 자동 조절해 밤에도 ISU 윤곽이 보인다. 톤 매핑은 CI 색 검증 기준인 ACES를 유지한다.
- 성능: 하늘을 픽셀마다 직접 계산한다. 이 PC의 실제 GPU에서 50fps를 넘지 못하면 저해상도 하늘 텍스처 캐시로 바꾼다.

## 3. 물

- 수면 판을 수평선까지 충분히 넓히고 거리 안개로 하늘과 잇는다. 선명한 수평선 한 줄과 그 위의 밝은 띠만 남긴다.
- 잔물결 법선: `tools/blender/bake_water_normals.py`가 Blender 5.2의 Ocean 모디파이어로 이어 붙일 수 있는 법선 지도를 굽는다. 데스크톱 1024px, 모바일 512px WebP로 `apps/web/public/images/login/water-normal.webp`와 `mobile/water-normal.webp`에 저장한다. `provenance.json`에 생성 스크립트, 명령, SHA-256을 기록한다. 기존 `texturesReady` 약속으로 로딩 완료와 실패를 알린다.
- 셰이더는 법선 지도를 큰 너울, 중간 물결, 잔물결의 세 겹으로 방향과 속도를 달리해 흘린다. 멀리 있는 부분은 밉맵으로 부드럽게 한다.
- ISU 반사: Reflector 거울 반사를 유지한다. 반사 좌표를 수면 법선으로 조금만 흔들고 가까운 곳은 선명하게, 먼 곳은 세로로 길게 끊기게 한다. 현재의 세 샘플 흐림은 뺀다.
- 각도별 반사율: Schlick Fresnel(F0 0.02)을 쓴다. 발밑은 하늘 밝기를 따르는 깊은 청록 물속 색이 보이고, 멀어질수록 하늘과 ISU 반사가 강해진다.
- 햇빛 길: 기존의 가짜 빛길, 반점, 줄무늬를 지운다. 잔물결 법선에 GGX 반사광을 계산하고 거리에 따라 거칠기를 키워 가까운 굵은 반짝임과 먼 곳의 넓은 빛길을 만든다. HDR 값이 빛 번짐으로 반짝임에 광채를 더한다. 해가 카메라 뒤에 있는 오전에는 빛길이 없다.

## 4. 호버 물결

- 기존 방향성 자취, 12개 물결 배열과 비 물결을 지운다.
- `isu-ripples.ts`: ISU 앞쪽 36x36 단위 수면에 256x256 파동 방정식 계산을 둔다. 반정밀도 렌더 타깃 두 개를 번갈아 쓰고 매 프레임 두 패스를 실행한다.
- 포인터가 수면 위를 지나면 반지름 약 0.25 단위의 작은 눌림을 포인터 속도에 비례해 넣고 상한을 둔다. 블록과 로그인 카드, 링크, 버튼, 입력 위에서는 넣지 않는다. 물결은 약 1.5초 안에 사라진다.
- 파동은 수면 기울기에 더한다. 반사 좌표 흔들림은 0.004 이하로 제한한다. 흔들림은 반짝임과 하늘빛의 일렁임으로 보인다.
- 사용자는 이전에 동심원 고리를 싫어했다. 포인터가 멈춘 뒤 생기는 고리는 강한 감쇠로 1초 안에 사라지게 하고, 캡처로 먼저 확인받는다.
- 터치의 탭과 드래그는 마우스와 같은 경로로 반응한다. `data-ripple-energy`는 파동 에너지 값으로 유지한다.

## 5. 파일, 대체 이미지, 검증

바뀌는 파일은 다음과 같다.

| 구분 | 경로 |
| --- | --- |
| 교체 | `apps/web/app/login/isu-water-moods.ts`를 `isu-day-cycle.ts`로, `tests/unit/isu-water-moods.test.ts`를 `isu-day-cycle.test.ts`로 |
| 수정 | `apps/web/app/login/isu-water-scene.ts`, `apps/web/app/login/isu-water.ts`, `tests/e2e/login-water.spec.ts` |
| 신규 | `apps/web/app/login/isu-ripples.ts`, `tools/blender/bake_water_normals.py`, `apps/web/public/images/login/water-normal.webp`, `apps/web/public/images/login/mobile/water-normal.webp` |
| 재생성 | `apps/web/public/images/login/login-still-desktop.webp`, `login-still-mobile.webp`, `provenance.json` 항목 |
| 문서 | `docs/PROGRESS.md` 새 절, `docs/LOGIN_VISUAL_HANDOFF_2026-09-27.md` 파일 표 |

- 캔버스 속성 `data-mood`, `data-next-mood`, `data-phase`, `data-transitioning`, `data-elapsed`를 없애고 `data-day-time`, `data-daypart`, `data-sun-elevation`, `data-sun-azimuth`를 둔다. 기존 `data-sun-x`, `data-sun-height`, `data-sun-strength`는 없앤다. 다른 속성은 유지한다.
- `LoginScene.tsx`, 슬로건, 로그인 카드, 인증 코드는 바꾸지 않는다. 이전 설원 장면 파일(`isu-scene.ts`, `isu-post.ts`, `isu-landscape.ts`, `isu-glow.ts`)은 현재 로그인에서 import하지 않지만 이번에 지우지 않는다.
- 다른 작업 소유의 미커밋 파일 다섯 개를 stage, 수정, 삭제하지 않는다. `login-motion.ts`는 줄바꿈만 달라 내용은 같다.
- 정지 대체 이미지는 해가 진 직후 어두운 푸른 시간의 장면을 폼과 HTML 문구 없이 다시 캡처한다. 기존의 어두운 대체 화면 가독성 검사를 그대로 통과해야 한다.

성공 기준:

1. 단위 검사: 주기 120초, 해가 +z에서 떠서 -z 쪽으로 진다, 0.1초 간격에서 해 방향이 튀지 않는다, 밤 15초 ±1초, 새벽과 노을 구간 각각 11.5초 ±1초, 첫 시각 무작위.
2. 시각 확인: 데스크톱 1440x900의 새벽, 일출, 아침, 한낮, 노을, 밤과 390px 모바일 노을, 호버 전후를 기존 가상 RAF 방식으로 캡처한다. 참고 사진과 비교한 뒤 사용자에게 보이고 확인받은 뒤에만 커밋한다.
3. 호버: 수면 위를 지나가면 `ripple-energy`가 오르고 멈춘 뒤 2초 안에 0 근처로 돌아온다. 블록 호버 빛, 터치 반응, 모바일 배치 e2e를 유지한다.
4. 성능: 앱 내장 브라우저(이 PC의 실제 GPU)에서 1440x900으로 10초 동안 평균 50fps 이상. 측정값을 그대로 기록한다.
5. `pnpm check`, `pnpm test`를 실행한다. 고유한 Compose 프로젝트로 Docker production 빌드와 `login-water`, `login-scene` e2e를 실행하고 AGENTS.md 8번 규칙대로 전용 자원만 정리한다. 확인용 `ax-water-demo-20260926`에는 이미지만 적용하고 DB와 파일 volume은 보존한다.
6. `docs/PROGRESS.md`에 실제로 실행한 명령과 결과만 기록한다. 실행하지 않은 검사를 통과로 적지 않는다.

## 진행 방식

구현은 `main`에서 만든 `login-daylight-water` 브랜치에서 한다. 커밋과 푸시는 사용자가 요청할 때만 한다. 외부 CDN, 외부 AI, 텔레메트리는 연결하지 않는다.
