# 공통 신청서 실행 계획

[신청서 설계안](../specs/2026-11-11-request-form.md)의 후속 계획이다. 아래 경로는 교육 모듈 구현 시 생성하거나 확장할 대상이다.

1. **작성과 검토 예시** (AC1, AC2의 화면 부분, AC6). `apps/web/app/design-system/`에서 가상 과정, 사유 입력, 읽기 전용 검토, 수정 복귀를 연결한다. 과정 선택 팝업의 적용/취소와 Base UI 포커스 복원 방식을 재사용한다. 브라우저 E2E로 키보드와 모바일 입력 보존을 확인한다.
2. **본인 초안 저장/조회** (AC2, AC5). `packages/contracts`, `packages/core`, `packages/server/db`, `packages/server`에 교육 신청 타입, 권한, 마이그레이션과 Service를 추가하고 `apps/web/app/api`와 ‘내 신청’ 화면을 연결한다. 격리 PostgreSQL 통합 검사로 타인 접근 거부와 rowVersion 충돌을 확인한다.
3. **제출과 접수 상세** (AC3~AC6). 같은 Service 안에 검증, 멱등 제출, 번호 발급과 성공 감사 기록을 원자적으로 구현한다. 동시 요청, 응답 유실 재시도, 마감된 과정, 제출 후 재수정을 통합 검사하고 브라우저에서 새 작성부터 실제 접수 상세까지 확인한다.

## 실제 결재를 붙이는 순서

작성/검토 예시는 독립적으로 만들 수 있다. 실제 상신과 결재는 다음 순서로 제안한다.

1. **사원과 조직 기준정보.** ‘인사/조직’에서 로그인 계정에 연결된 사원의 현재 소속과 조직 책임자를 확인한다. 관리자는 계정 연결과 책임자를 변경한다. 과거 기준일 조회에는 발령 및 책임자 이력이 별도로 필요하다. [현재 스키마](../../../packages/server/db/schema.ts)
2. **교육 신청의 결재선.** 첫 정책 후보는 소속 책임자 1단계다. 서버가 상신 시점의 신청자 소속, 결재자, 순서를 기록한다. 책임자를 찾을 수 없으면 이유를 안내하고 초안을 유지한다. 승인자 결정과 조직 이동 후 기존 건의 처리 방침은 운영 정책으로 확정한다.
3. **내 결재함.** 지정된 결재자가 대기 건을 승인/반려할 때 현재 권한과 처리 순서를 다시 확인한다. 중복 클릭과 동시 처리에도 상태 변경과 감사 기록은 한 번만 남아야 한다.
4. **두 번째 업무로 재사용 확인.** 구매요청을 후보로 둔다. 요청 목록, 작성/검토, 결재함을 함께 쓰되 구매 품목과 금액 검증, 발주/입고 전환은 구매 Service가 담당한다.

교육 과정 원장과 모집 상태의 소유자도 실제 접수 전에 정한다. 조직별로 휴가, 비용 등 업무에 따라 승인자를 지정하는 사례는 조직도와 업무별 결재 규칙을 설계할 때 참고할 수 있다. [Frappe HR 부서 설정](https://docs.frappe.io/hr/department)
